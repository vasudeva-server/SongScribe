⏺ Workflow for Multiple Feature Branches into Develop

  Goal

  Maintain a linear develop history while integrating work from multiple branches, and keep your feature branch in sync.

  The Right Approach

  1. Before merging: ensure feature branches have sequential ancestry

  When you have multiple feature branches (e.g., feat/feature-A and feat/feature-B), they should ideally branch from the same point or have
  clear temporal ordering.

  # If feat/feature-B was created before feat/feature-A merged:
  git checkout feat/feature-B
  git rebase develop    # Bring it forward to develop's tip

  2. Merge the first feature branch

  git checkout develop
  git merge --ff-only feat/feature-A    # or --no-ff if you prefer merge commits
  git push origin develop

  3. Merge the second feature branch

  git rebase develop    # Rebase it onto the updated develop first
  git checkout develop
  git merge --ff-only feat/feature-B
  git push origin develop

  This keeps history linear: develop has commits from A, then commits from B, in sequence.

  4. Bring your working branch up to date

  If you're actively working on feat/abc2svg-port, rebase it onto the updated develop:

  git checkout feat/abc2svg-port
  git rebase develop
  git push -f origin feat/abc2svg-port  # Force-push if you rewrote history

  Avoiding Divergent History

  Problem you hit:
  - feat/abc2svg-port branched from commit X
  - feature/single-bar also branched from commit X (or earlier)
  - Merged feat/abc2svg-port first → develop has feat/abc2svg-port's commits
  - Merged feature/single-bar second → Git created a merge commit instead of linear history

  Why it happened:
  When both branches share a common ancestor but diverged independently, merging them creates a fork that Git joins with a merge commit.

  Solution:
  Always rebase second/later branches onto develop before merging, so they're based on the first branch's work.

  Recommended Workflow (Linear Develop)

  # 1. Merge branch A
  git checkout develop && git rebase feat/feature-A
  git merge --ff-only feat/feature-A
  git push origin develop

  # 2. Before merging branch B, rebase it onto develop
  git checkout feat/feature-B
  git rebase develop
  git push -f origin feat/feature-B

  # 3. Merge branch B
  git checkout develop
  git merge --ff-only feat/feature-B
  git push origin develop

  # 4. Keep your branch in sync
  git checkout feat/abc2svg-port
  git rebase develop
  git push -f origin feat/abc2svg-port

  Key Rules

  1. Always rebase feature branches onto develop before merging (if they're not already up-to-date)
  2. Use --ff-only merges to prevent unnecessary merge commits
  3. After pushing to develop, immediately rebase your working branch to stay in sync
  4. Never merge develop into a feature branch — always rebase instead (keeps history linear)

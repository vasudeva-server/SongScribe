### 12 summary

**61 behavior rows: 49 unit / 6 e2e / 6 none; of 55 testable, 22 adequate · 32 missing · 1 inadequate · 0 wrong-level · 0 redundant (~60% dark).** The package is two opposite halves. **`Shutdown` is the single best-covered class in the entire audit** — its mirrored `lifecycle/ShutdownTest` exhaustively asserts the confirm→EDT→JVM phase order (LIFO per phase), every veto branch (first/middle confirm), cleanup exception-vs-error propagation, re-entrancy guards (from confirm, from cleanup, second-call), per-phase tag-namespace uniqueness, `CleanupTask` at-most-once both serially and under an 8-thread race, and the JVM-hook cross-path at-most-once invariant; the three `e2e/ShutdownTest` cases cover the real `QuitAction`/`windowClosing` exit wiring (22/24 testable adequate). **Everything else in scope is essentially dark.**

Key shape:
- **(1) highest-risk gap — `RuntimeError` is 100% untested.** The application's universal fatal-error escalation point, called from ~35 production sites, has **zero tests of any kind** — including its two safety-critical contracts: the re-entrant `ALERT_SHOWN` CAS guard (prevents double-exit) and `ExitInProgressError extends Error` with suppression/stack-trace disabled (the type `SongScribe.main`'s uncaught-exception handler keys on to keep the EDT alive during a fatal dialog). Direct unit testing is blocked by the bare `System.exit(-1)` inside `showDialogAndExit`; the project needs a one-time decision on an exit seam (interceptor / `SecurityManager` shim) rather than leaving this path permanently dark.
- **(2) boot-time logging setup is dark on every launch path.** `SongScribe.configureLogging` / `resolveLogDir` / `truncateLogIfRequested` — run on all seven launchers — are pure branch logic (three-way platform path: macOS `~/Library/Logs/SongScribe`, Windows `APPDATA`-or-`user.home` fallback, other `~/.songscribe/logs`; `mkdirs()`-failure → null; `LOG_LEVEL` upper-casing; `CONSOLE_LOG` resource override; `TRUNCATE_LOG` delete + `IOException` swallow) and entirely untested.
- **(3) `main` dispatch is unit-testable but untested.** App-selection (`args[0]` vs the `songscribe` system property vs default `"sw"`), the `"…converter"` banner-title branch, the macOS `apple.*` system-property pre-AWT setup, and both arms of the uncaught-exception handler (`ExitInProgressError` swallow on EDT vs `RuntimeError.exit` dispatch off-EDT) are all pure logic; only the default GUI-boot branch is genuine e2e.
- **(4) `logBanner` is `inadequate`** — invoked as an assertion-free setup side-effect in `UnitTest.suppressDialogs` and `E2ETest.initMainFrame`; it cannot fail regardless of what it logs.
- **(5) two low-risk `Shutdown` unit gaps** — the `now()` off-EDT `IllegalStateException` guard and the `runJVMTasksFromHook()` outer `Throwable` boundary catch — plus one **missing e2e**: `CloseWindowAction` is a distinct quit entry point and, unlike `QuitAction`, its `Shutdown.now()` wiring is not exercised by `e2e/ShutdownTest`.

**Carry-forward (data-loss guard, open since Sessions 5/7):** `MainFrame.showSaveDialog()` + the `save`/`saveCurrentFile`/`saveAsNewFile` chain intersect `Shutdown` only through `e2e/ShutdownTest`'s dirty-doc `windowClosing`-veto case; the Don't-Save / Save-propagate branches remain dark. `MainFrame` itself stays Session 7 scope — not re-audited here. This thread now closes out as a known-open remediation item: no further audit session owns it, so it must be picked up during the rewrite.

**Dead code (verified zero references via serena `find_referencing_symbols`):** `FileExtensions.SONGSHOW` (`"msss"`), `FileExtensions.SONGBOOK` (`"mssb"`), `FileExtensions.SBPORTABLE` (`"msbp"`) → delete in remediation (only `SONGWRITER` = `"mssw"` is live). No dead code in 12A.

**Production observations** (filed as a tracked GitHub issue, #417):
1. **(testability — critical path)** `RuntimeError.exit` calls `System.exit(-1)` directly with no test seam, leaving a ~35-site fatal-error path that cannot be unit-tested without process-exit interception. Decide on an exit abstraction once and apply it.
2. **(dead code → delete)** `FileExtensions.SONGSHOW` / `SONGBOOK` / `SBPORTABLE` have zero references anywhere in `src/main` or `src/test`.
3. **(test-quality)** `logBanner` is called purely for side effects in `UnitTest.suppressDialogs` and `E2ETest.initMainFrame` with no assertion — false-confidence coverage; either assert on captured log output or drop the pretense of it being tested.

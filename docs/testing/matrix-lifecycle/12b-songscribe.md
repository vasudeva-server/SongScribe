**12B notes (quality concerns):** The most significant gap is that `SongScribe.configureLogging()` — which is called by seven different entry points (all converter `main` methods plus `SongScribe.main` itself) — has no tests at all. Its three-way platform branch in `resolveLogDir`, the APPDATA fallback, the `mkdirs` failure path, and the `LOG_LEVEL` uppercasing are all untested logic. The `logBanner` call in `UnitTest.suppressDialogs` and `E2ETest.initMainFrame` looks like coverage but is a quality defect: it is invoked as a setup side-effect with no assertion, so it can never fail regardless of what `logBanner` produces. The `main` dispatcher's app-selection logic (args vs. system property vs. default) is pure string/branch logic that is fully unit-testable without touching Swing but has no tests. Three `FileExtensions` constants (`SONGSHOW`, `SONGBOOK`, `SBPORTABLE`) have zero references anywhere in the production codebase (confirmed via serena `find_referencing_symbols` returning empty results for each); they appear to be dead legacy symbols worth flagging in a GitHub issue. Only `SONGWRITER` is actively used.

**Notes:**

`DialogsTest` (e2e) is partially misplaced. Three of its five tests duplicate coverage already provided by the unit `songscribe/ui/DialogsTest.WhenNotSuppressed` suite: the CLOSED_OPTION→NO_OPTION mapping (row 3774), the CLOSED_OPTION→CANCEL_OPTION mapping (row 3773), and the `showInputDialog` text-return path (row 3777) are all asserted at unit level via mocked `JOptionPane` construction with stubbed return values. The e2e versions add only that a real robot Escape-press or text-type produces `CLOSED_OPTION` / input text from a live `JOptionPane` — which is Swing framework behavior, not SongScribe production logic. `testClickYesReturnsYesOption` is wrong-level for a different reason: YES_OPTION involves no production mapping whatsoever (it is the raw `JOptionPane` return), so there is nothing in our code to verify. The one genuine e2e in `DialogsTest` is `testReturnsIndexOfClickedOption`: the `getOptionPaneResult` index-scan (matching the clicked value against the options array) is real production logic and the only non-suppressed test that exercises it.

All three `ShutdownTest` methods are genuine e2e. They verify that real `ActionEvent`/`WindowEvent` dispatch into the live `MainFrame`+`QuitAction` plumbing reaches `Shutdown.now()` and triggers the registry — a wiring risk that unit tests of `lifecycle/ShutdownTest` cannot cover because they call `Shutdown.shutdown()` directly, bypassing the entry-point dispatch entirely. The sentinel veto pattern is sound: it proves the shutdown sequence was reached without allowing `System.exit(0)` to terminate the test JVM. Note that §12A also flags a missing e2e for `CloseWindowAction` (row 3918, verdict: missing), which is a distinct quit entry point not yet covered by `ShutdownTest`.
